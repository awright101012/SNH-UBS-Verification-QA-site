Rules handle the known. Reviewers navigate what they have not seen. This agent is built for the space between.

Give it an employment verification with conflicting dates, incomplete evidence, and several possible handbook rules. It does not simply classify the row. It investigates.

First it asks for the timeline. Then it checks which evidence exists. It retrieves the rule governing date discrepancies. It notices that the missing primary-source evidence prevents a confident correction. Its final answer is not a guess: send the case to a person, with the rule, the evidence, and the missing proof attached.

AI moveWhat it learns
Show timelineprovided and verified dates differ
Check evidenceprimary-source proof is missing
Retrieve rulea committed correction requires supporting evidence
File decisionhuman review, with the missing proof identified

This is not autocomplete. It is an evidence-seeking sequence in which each answer determines the next question. (Synthetic, like every worked example on this page.)

Give it the missing source and the same investigation continues: compare the dates, apply the discrepancy rule, file a supported return, and attach the evidence.

The AI is not designed to stop on every difficult case. It is designed to go exactly as far as the evidence supports.

The enabler

The harness gives the intelligence somewhere safe to work

The model reasons inside a deliberately prepared world: safe facts, relevant rules, read-only tools, and a clear decision contract. The harness prepares that world, checks the resulting argument, and decides what may leave.

That division of labor is the product. The AI provides the intelligence. The harness gives that intelligence a trustworthy way to operate.

PEOPLE OWN

Genuine judgment calls, new precedents, and the final application of any correction.

The world, precisely

The model can reason freely inside a world the harness defines

1 · What it sees. Identity and free text are removed before the model enters.

2 · What it can ask. Seven read-only tools; no writes, updates, or outside actions.

3 · Which rules exist. The harness supplies the only rules the model may cite.

4 · What it may return. Three legal answers on one fixed form.

5 · What counts as proof. Every committed answer needs a real rule and real evidence.

6 · What happens next. The harness — not the model — chooses the final route.

Everything before the model prepares its world. Everything after it verifies what survives.

THE EIGHT STAGES, MODULE BY MODULE

Drawn as a pipeline, the model occupies one box. Everything before it controls what it sees; everything after it controls what survives:

01 — Normalizer. One raw warehouse row goes in; an anonymized fact packet comes out. Free-text fields — notes, comments, names — become yes/no presence flags. Search identifiers are replaced by salted stable hashes. The packet itself carries the assertion that raw text was excluded, and from this point on, nothing downstream ever touches it.IN raw warehouse row · OUT anonymized fact packet

02 — PrePolicy. Deterministic gates run before any model is considered. Hard blocks short-circuit straight to human review: a product outside the supported education/employment scope, or missing lifecycle evidence. Soft gates — absent field-level proof, unmapped status codes, a missing diff count — don't stop the pipeline, but they chalk evidence gaps onto the case that the verifier will later use to refuse any confident fix built on them.IN fact packet · OUT pass / review / block — plus chalk-marked evidence gaps

03 — Rule selector. The 25-rule QA-manual rulepack is scoped to the product at hand. This selection matters more than it looks: it becomes the model's citation universe. Anything the model cites outside this set is grounds for a block.IN rulebook + product · OUT the citation universe: the only rules the model may cite

04 — Reasoner. The LLM, deliberately bounded. The current hosted reasoner is Qwen3.6-27B, pinned to one provider and one configuration with fallbacks disabled, at temperature 0; a local copy occupies the same interface for inexpensive iteration. The prompt is two messages — a versioned system prompt loaded from data, and one JSON payload — and decoding is constrained to the decision schema. The interface is one method — hand it a case, get a draft decision — and a deterministic stub implements the same interface. Replaceable, literally — and the same slot has a second occupant: a reasoner that gathers its own evidence first (the tools).IN packet + rules + allowed ids · OUT one evidence-backed draft, ready for independent verification

05 — Verifier. Re-derives every checkable claim in the model's output from the inputs: schema, citations, confidence, catalog codes, data safety. Detailed below, because this is where the system's personality lives.IN the draft + everything upstream · OUT six re-derived pass/fail verdicts

06 — Finalizer. Maps decision + verifier result + prepolicy result onto exactly one of ten terminal dispositions. Anything questionable is forcibly rewritten into a human-review routing before it leaves the building.IN draft + verdicts + gates · OUT exactly one of ten dispositions

07 — Trace. Every case emits one append-only audit line: prompt-template hash, rulebook hash, input hashes, both verifier error lists, the disposition, and the recorded reason whenever a case was forced to a person. The raw model exchange is archived out-of-band and referenced by hash — the trace itself stays free of model prose.IN the whole journey · OUT one append-only audit line — hashes, verdicts, reasons

08 — Eval. Aggregation over traces: disposition counts, human-review rate, catastrophic-error pattern matches (invented citation, unsupported direct correction, data-safety hit, malformed JSON), and a promotion-blocked flag that any catastrophic error flips. It also computes the number I actually manage the project by — more on that below.IN all traces · OUT disposition mix, error patterns, promotion verdict, engine-vs-model share

The contract

Every answer arrives with its evidence attached

The decision is a signed form, not a chat reply. The AI must choose one of three answers — fix it, accept it, or send it to a person — and attach the rule, evidence, requested correction, confidence, and review requirement. Decoding guarantees a valid form; the verifier determines whether its reasoning earns a committed route.

THE FULL CONTRACT: DEFAULTS AND DECODING

Two details are doing quiet work here. First, the default object is the safe object: a freshly constructed decision defaults to human review, at confidence zero, with review explicitly required. Anything that fails to fully overwrite the defaults decays toward a human, not toward an approval.

Second, the schema is enforced at decode time, not requested politely. Early runs let a 9B model freestyle "JSON-ish" output, and it rendered the nested objects as prose strings — zero of five responses parsed. Switching the serving stack to schema-guided decoding took parse success to 58–60 out of 60 in the same stage. The lesson stuck: "it parses" is a property of the decoding mode, not an achievement of the prompt. And parsing still buys no trust — the strict parser and the verifier treat every response as hostile regardless of how it was decoded. A response that fails to parse is stamped invalid at the schema layer, which the verifier then rejects, which the finalizer then blocks. Every failure falls the same way: toward a person.

The tools

The model can ask questions. It still cannot act.

The one-shot reasoner receives the safe packet at once. The tool-using reasoner builds the same view through read-only lookups, one question at a time. Both return the same locked form and face the same verifier; only the one-shot path has completed the full benchmark.

The menu is seven read-only lookups: timeline · evidence flags · result-code meaning · comment-code meaning · safe value comparison · rule lookup · product context.

THE SEVEN LOOKUPS, PRECISELY
get_lifecycle

The case's timeline and product context, in safe form.

get_checkpoint_window

What the pre-decision window covers — aggregates only.

get_evidence_flags

Which evidence exists and whether proof is available, as flags.

lookup_result

The authoritative meaning of one result code.

lookup_comment

The authoritative meaning of one comment code.

compare_fields

Provided-vs-verified value families, compared in safe terms.

get_rules

The selected rule and citation ids — the citation universe, again.

The exciting part is not that the tools are restricted. It is that the model can conduct a small investigation: it chooses what to inspect next, reads the answer, updates its view, and continues until it can file a decision or identify what remains unknown.

Every lookup leaves a receipt. The verifier holds the model to what those receipts actually contain.

Repeated questions, invalid tools, unsafe output, or an exhausted budget all end the same way: stop and send the case to a person.

After the model

The AI builds the argument. The harness checks every step.

The AI produces the argument. The verifier rebuilds each check from the same case facts, rules, and receipts. Six checks run in a fixed order — data safety first:

data_safety_ok

A recursive sensitive-pattern scan (emails, phones, SSNs, URLs, filenames) over the entire decision object.

citation_membership_ok

Every citation must be a member of the selected rules ∪ evidence ids. Invented citations die here, not in a postmortem.

material_support

A committed decision must cite at least one rule and one piece of evidence — and the cited rule must actually govern the outcome claimed.

confidence_ok

needs_fix or correct_as_is below 0.65 confidence is refused: confidence_too_low_for_final_decision.

direct_correction_ok

"It was directly corrected" requires field-level old/new proof, which the normalizer currently never grants. The claim stays candidate-only.

unknown_mapping_ok

Observed qastatus/errorcategoryid codes may be echoed as values under caveat — never interpreted as meaning.

This is where trust is created — and the next section shows it catching a real mistake.

The blindfold

What the model never sees

Assume every prompt will eventually appear somewhere unintended. The hosted path therefore receives no names, contacts, identifiers, free text, or raw values. The same scanner runs before send and after return; any hit stops the case.

Two payload tiers enforce the boundary: an export-safe tier for hosted models and a richer local-only tier for controlled evaluation. A missing tier is treated as local-only and refused.

THE PAYLOAD BOUNDARY, PRECISELY

The first layer is an assertion that runs on every payload before send, rejecting the prompt outright if it contains any forbidden key:

searchidsubjectidsuborderidubsiclientiduseridusernameactor_nameraw_rowsource_filesource_filesinput_filesinput_hashessource_labels

— and then runs the full sensitive-pattern sweep plus a path-pattern scan (drive letters, home directories, data-directory names, file extensions) over everything that remains. The export-safe tier carries field families, counts, hashed keys and evidence references — no values. The richer local-only tier may add position-title, degree, and graduation-date values — never names, contacts, identifiers, or free text — and an egress firewall in the client refuses to send anything above the safe tier to a hosted provider.

The replay benchmark adds a temporal blindfold on top: every column that records what the human QA reviewer eventually did — outcomes, statuses, notes, rework flags, everything post-decision — is on a withheld-keys list, so the model predicts from the same pre-decision fact surface the original reviewer had. Without that, a replay benchmark quietly becomes a label-leaking parlor trick.

FIELD NOTE — WHEN THE GUARD DOG BITES YOU

The sensitive-text scanner once blocked 12 of 320 replay rows before any model was called. The phone-number regex, written with naive digit boundaries, was matching ten-digit runs inside the harness's own 20-character hex hashes — the very hashes the normalizer substitutes for raw identifiers. The guard was eating the disguise it had issued.

The fix was hex-aware boundaries. The lesson was bigger: the safety guards need their own tests, because a paranoid guard also defaults to "send it to a human" — silently, consistently, and at a 4% tax you won't notice unless you're counting.

The payoff

The model is the replaceable part

The harness does not depend on one model being permanently best. A better model can take the same safe facts, tools, rules, and decision contract — and face the same independent checks.

The intelligence can improve without rebuilding trust from scratch.

The engine

The boring path is the best path

The AI handles unfamiliar questions. Once people settle one, it graduates into precedent, and the next matching case moves through code.

The precedent ledger turns confirmed rulings into code. A complete match with complete context skips the model entirely; missing context closes the shortcut. The ledger starts with 24 handbook-seeded pair rulings — the seeds establish the mechanism, and reviewer-confirmed rulings are what compound it. The eval splits every decision — settled by precedent, settled by the gates, or needing the model — and tracks one number: how often the model was needed at all.

Every confirmed precedent makes the next matching case faster, cheaper, and easier to audit.

The baseline

The loop being shortened, measured first

Before claiming the harness shortens QA, I measured the existing loop — one reproducible script over hundreds of thousands of finalized education and employment verifications from the first half of 2026. Rework usually begins in under an hour; approval returns roughly eight days later.

The proof

The benchmark was built to disappoint us

Claims are only as good as the instruments that check them, so the instruments came first: canaries gate every batch (one miss quarantines it), golden sets score known answers, and the replay benchmark asks the only honest question — given what was knowable that morning, can the system predict the action the human took? The blind slice has never been run.

First reveal: the local and hosted lanes matched on every canary, but only a quarter passed. That makes local results useful for screening, not promotion; what you fix locally still returns to the hosted lane for final validation.

Second reveal: an early sample suggested an 82% result. Full scale brought it back to about 54%. The gates caught the mirage before anyone saw it as a claim.

PROMPT LINEAGE, GENERATION BY GENERATION

Prompts are versioned data with lineage. Prompt packs carry a generation number and a parent id, live in a candidates directory, and change one thing per generation. Gen-0 abstained everywhere — 6/24 canaries, mostly citation blocks. Gen-1 ported citation discipline and moved to 10/24 with zero citation blocks. An intermediate replay pack that scored well on approvals turned out to be an approve-machine with a return-recall of zero — caught by per-class recall, killed, and recorded in the lineage like everything else.

The lab can run an experiment on its own; it cannot promote its own result. A lab loop runs a prompt generation end to end; a gate-check scores it against the promotion gates — pointed at the real full-dev results, it correctly returned not passed; a registry tracks pack lineage; a sentinel watches for drift. Promotion into the ledger remains a human-only action.

Third reveal: the model and the fixed rule both scored about 54% — a statistical tie. With richer safe evidence, the comparison moved to about 59% versus 56% — roughly a three-point early signal, and the next round's target.

The project did not produce a model victory. It produced a measuring system willing to say so — the tie tells us the reasoning still needs improvement, and the roughly 3% of benchmark cases where model and rule disagreed became precedent candidates, not prompt fuel.

The takeaways

What this changed in how I build

  • Give AI the messy work; keep authority in the harness. The model navigates ambiguity. The harness decides what may survive.
  • Make evidence part of the interface. A recommendation is incomplete until its support travels with it.
  • Constrain structure; verify meaning. The schema shapes the answer. The verifier decides whether it is supported.
  • Turn settled judgment into infrastructure. Confirmed answers move repeat questions into code.

The compounding idea

The system gets smarter in two ways

Better evidence, prompts, and models improve the AI. Confirmed rulings improve the harness by moving repeat questions into code.

The AI gets better at unfamiliar cases. The harness makes familiar cases disappear.

The AI provides the intelligence. The harness turns it into a decision we can trust.

Two constraints, stated plainly. First: these are elapsed clocks, not handle time. Nothing in the data records the minutes a reviewer spends inside a case; the closest available proxy is event footprint — 17 QA actor ids, 2,337 ledger events, 575 actor-days, median 2 events per active actor-day — which measures activity density, not labor. What the baseline licenses is architectural, and only this: the harness runs its checks at draft time, in seconds, on every case, against the same rule territory that produces 85.6% of coded return reasons. Each return pre-empted at the draft is one measured multi-day round trip that never starts — and because the baseline is a script, not a slide, the deletions will be counted the same way the detours were.

EVAL APPARATUS: CANARIES, GOLDENS, REPLAY SPLIT

Canaries gate every batch. Twenty-four synthetic cases with known expected outcomes run through the live reasoner before any real batch. A single miss quarantines the whole batch — no override in the path. Golden datasets back them up for scoring: 10 hand-built cases in v1, 51 in v2 (34 synthetic handbook-truth, 17 masked observed-rework), plus curated train/test seeds of 187 and 52 rows.

The replay benchmark asks the only honest question available. Given the pre-decision fact surface, can the system predict the QA action the human historically took? Labels are stamped as what they are — the historical human action, not adjudicated truth — and scoring aggregates at search level, because events cluster within searches and event-level accuracy flatters you. The 3,156-event corpus is split once, deterministically: a dev slice of 136 searches (2,146 rows) and a blind slice of 64 searches (1,010 rows) that has never been run. It unlocks only in an explicit proof mode, and only after promotion gates pass.
